# Security hardening 0.7.0

This release is an application source review and remediation, not an independent penetration-test certificate. Schema version 3 is unchanged. Keep the 0.6.2 backup, stop all replicas/workers, overlay the changed files, rebuild production images and verify migrations, content, search and audit before reopening traffic. Use the previous image/code if rollback is required; no new DDL is performed.

## Review and remediation

| Boundary | Finding in 0.6.2 | Remediation and regression |
| --- | --- | --- |
| Git and OIDC network clients | HTTP wrapper timeout was per operation, not a total response deadline; framing handled differently from managed proxy | Shared pinned TLS socket, verified hostname, no redirects, monotonic connection/handshake/write/read deadline, bounded framing and raw payloads. GitLab/OIDC actual HTTPS tests and security-transport.py. |
| Managed API / webhooks | Final chunk accepted before complete trailer section | Require complete bounded trailer terminator, reject malformed or framing/security-sensitive trailers; reject duplicate length or TE+CL including HEAD. |
| HTTP routing | Strict target validation depended on domains configuration | Validate original origin-form target before routing in App and exporter, reject ambiguous slashes, dot segments and encoded separators. |
| Browser state changes | Existing CSRF token checks did not independently check cross-origin browser metadata | Reject supplied conflicting Origin and cross-site/same-site Fetch Metadata for browser POST. Existing CSRF remains mandatory; bearer CI and signed webhooks retain their own authentication. |
| OIDC | Audience/key-operation type checks permissive | Require bounded audience lists of strings, suitable JWK verify usage and bounded key set; existing RS256, nonce, issuer, state and PKCE checks preserved. |
| Import | Size measured separately from opened source; partial ZIP staging could remain after failure | Open once, regular-file fstat, bounded copy, private file/fsync, rollback reservations and staged files on error. Existing path, expanded size, CRC and entry checks retained. |
| Build | Test source/fixtures shipped in runtime image | Explicit runtime copies and separate test target. Default production image excludes tests; CI scripts select test explicitly. Apache TRACE disabled, reduced server disclosure and nosniff on static assets. |

Review also traced identity/workspace RBAC, published-page SQL and media visibility, Markdown sanitization, OpenAPI reference resolution, backup integrity and audit chains. Existing tests were retained; no claim of exhaustive coverage or absence of other defects is made. The bundled CJR TemplateSandbox eval is a reviewed exception to the narrow local SAST rule: compiled trusted templates only; never place uploaded user content in executable templates. PostgreSQL owner and deployment administrators remain trusted.

## Network and browser policy

Managed Playground and webhook destinations and public GitHub/GitLab require globally routable IPv4 DNS answers. The actual TLS connection is made to the checked IP with the original hostname and CA verification; no ambient HTTP proxy or redirects. Explicit operator-approved internal GitLab origins and configured OIDC issuer/endpoints may resolve to private addresses: restrict these configuration settings to trusted operators and use egress ACLs. System DNS lookup is synchronous; use a bounded trusted resolver, network egress controls and process timeouts. The transport deadline bounds socket I/O and counts elapsed DNS time but cannot interrupt a blocked OS resolver. Do not enable untrusted private origins. TLS 1.2/1.3 only; install enterprise CA in the system trust store, never disable verification.

Browser POST accepts same-origin metadata or absent metadata with the original CSRF check. The original Host (including non-default port) must reach the application. When BOOK_PRIMARY_HOST is configured, browser Origin must be HTTPS on that host; externally terminated TLS without primary configuration must preserve Host and secure-cookie settings. Nginx strips externally supplied internal edge credentials; Caddy remains responsible for setting trusted ingress metadata. Rejecting encoded path separators is intentional; encode search/query values in the query string, not the path. Sensitive identity routes use no-referrer. CI/webhooks require their own credentials, not browser cookies.

## Verification and gate

Run `php tests/security-hardening.php --require-zip`, `python3 tests/security-http.py`, `python3 tests/security-transport.py` on a development host. The native suite includes these plus existing TLS/OIDC/GitLab and functional tests. Run `python3 tests/release-gate.py --suite all --report-dir /tmp/book-release-070` on disposable infrastructure. The separate CI security-scan job is mandatory for enterprise-release. On a disposable build host with Composer, Semgrep and Docker run `sh tests/security-scan.sh /tmp/book-security-070`. It checks the locked dependencies, local PHP security rules, builds the actual production image, checks that tests are absent, and scans it with Trivy vulnerability/secret scanners. Nonzero scanner results block release; do not suppress findings to force a green gate. Restrict access to scanner reports if a secret is found. Review and remediate medium/low risks too. The narrow local SAST rules are not a comprehensive commercial SAST or DAST suite.

Use `BOOK_IMAGE_TARGET=test` only for isolated integration testing. Default production is `production`. Never deploy a test image. Rebuild all services after the update; schema 3 needs no additional migration. For full qualification, run the existing PostgreSQL/Redis/Sentinel/Caddy/S3/Chromium gates and independent penetration testing (RBAC/tenant isolation, OIDC, SSRF, upload/archive handling, CI/webhooks, proxy, recovery). No High/Critical vulnerability-free status is asserted without actual reports and retest. External audit anchoring, key rotation and role separation beyond existing migration credentials remain separate work; physical PITR and signed artifacts are later roadmap items.
