# Docusaurus → CajeerEngine Book 1.0.10

## Production import workflow

1. Back up the Book workspace and export the Docusaurus repository to a ZIP (or upload its directory in a browser that supports folder upload). The archive may contain one enclosing repository directory. Open **Studio → Import documentation** with Editor/Owner permissions.
2. Select the target **Book**. The **Version** field identifies the current `docs/` snapshot (for example, `2.0`). Historical `versioned_docs/version-1.1/` snapshots are imported into Book version `1.1`. **Choose a current version different from every historical version**, otherwise source paths may collide.
3. Choose **Update drafts**, **Skip existing pages** or **Rename**, upload the archive, and use **Preview**. Inspect the resulting version, locale, sidebar order, sections, warning list, links, and media count. Abort if the preview shows an unexpected target path.
4. Apply the preview. A CSRF/session/workspace-bound, integrity-checked, 15-minute preview token is required. The server revalidates all inputs and Book state under its write lock; the import is atomic with imported media and revision metadata.
5. Inspect the created drafts in the Studio. Publish them with the existing review/approval workflow. **Import never automatically publishes anything**, changes existing published snapshots, or changes Workspace visibility/permissions.

## Supported repository layout

```
docusaurus.config.js   # identifies a Docusaurus repository; never executed
sidebars.js            # static JS object literal only (sidebars.ts / sidebars.json also accepted)
docs/intro.mdx
docs/guide/index.md
versioned_docs/version-1.1/intro.md
versioned_sidebars/version-1.1-sidebars.json
versions.json
i18n/ru/docusaurus-plugin-content-docs/current/intro.md
static/img/logo.png
```

- **Versions:** Root `docs/` targets the version entered in the form. Every `versioned_docs/version-X/` directory targets Book version `X`. The matching `versioned_sidebars/version-X-sidebars.json` supplies navigation for that version. `versions.json` is validated, never executed. Each Book version has independent drafts and published pages.
- **Languages:** Supported language codes are `en`, `ru`, `de`, `es`, `fr`, `it`, `pt`, `pt-BR`, `uk`, `pl`, `tr`, `ja`, `ko`, `zh-Hans`, and `zh-Hant`. The `i18n/<lang>/docusaurus-plugin-content-docs/current/` and `version-X/` trees are imported with the corresponding locale metadata, in separate `<lang>/...` page paths. They are standalone localized drafts; automatic translation-group linking is not attempted because the source may not yet be published. Use Translation Studio after publishing if linked language variants are required.
- **Sidebars:** Static `sidebars.js`, `.ts`, `.json` and version-specific JSON/JS/TS configurations are parsed *as data*. Document IDs, categories, `items`, category `link: {type: 'doc'}`, and `autogenerated` directory entries map to Book's flat section/order navigation. Tab, plugin/theme, collapse and custom navigation rendering do not transfer. Unsupported dynamic JS/TS functions, `require()`, spreads, and expressions are rejected without being evaluated. For dynamic sidebars, export a static JSON sidebar first.
- **Pages:** `.md`, `.markdown`, `.mdx`, front matter `title`, `id`, `slug`, `sidebar_label`, `sidebar_position`, static links and local images. Docusaurus `index.md(x)` maps to a folder index route. Existing public Book URLs are not overwritten on import; conflict strategy applies to drafts only.
- **Admonitions/MDX:** `:::note`, `:::info`, `:::tip`, `:::warning`, `:::caution`, `:::danger` and `:::success`, including optional titles, are converted to Book callout blocks. Statically imported Docusaurus `<Tabs>` / `<TabItem>` and `<Admonition>` convert to native rich blocks. Existing safe static Mintlify MDX components (such as Steps, Cards, Accordion) are also recognized. Fenced examples are not executed or converted as active JSX. Unsupported dynamic JSX, `import`/`export` and expressions require manual migration. Review warnings and inspect previews.
- **Media:** Local PNG, JPEG, GIF, WebP, PDF, ZIP, TXT and CSV are saved using existing content-validated, immutable Book media blobs. `/img/...` URLs resolve against `static/img/...`; relative page links and supported absolute Docusaurus versioned URLs map to Book `/docs/{book}/{version}/{page}` routes. External resources are never downloaded. SVG, arbitrary JS/CSS, binaries, videos and executable components are excluded by current MediaStore safety policy.

## Operational guarantees and limits

The existing importer caps uploads at 200 entries, 64 MiB expanded, 20 MiB per file, 256 KiB per Markdown document and 1000 total Book pages. For larger sites split the repository by release/version. The source is staged into private files; ZIP entry paths, symlinks, collisions, CRC, and content MIME are validated. Imported assets may increase the workspace media quota. The importer never invokes Node.js or evaluates repository JavaScript.

New versions/languages do not require a PostgreSQL schema migration; they use the existing BookStore format. Back up the Book database and media folder (or PostgreSQL content store) before importing. For PostgreSQL deployments validate the operation on staging with a running server: the isolated PHP tests do not prove availability or performance of the production database.

### Validation

```
php tests/docusaurus-110.php
php tests/docusaurus-110-integration.php
php tests/mintlify-109.php
```

The integration test requires PHP 8.4, the Composer packages and `ext-zip`, `ext-mbstring`, and other extensions from `composer.json`. A successful local mock test does **not** establish deployment readiness; also run the full CI and test representative production bundles before rollout.
