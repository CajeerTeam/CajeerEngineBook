# Безопасность, приватность и операционные границы

[Обзор](README.md) · [Возможности](features.md) · [Развёртывание](deployment.md)

## Модель доступа

**Организация → Workspace → Book → страница.** Права на чтение и изменение задаются политиками видимости, членством, ролями и разрешениями соответствующего контекста. Публикация не должна обходить ограничения чтения; поиск и ссылки тоже должны применять авторизацию.

| Роль процесса | Возможности и ограничения |
| --- | --- |
| Читатель | Доступ только к опубликованным и разрешённым материалам |
| Участник/редактор | Работа в доступном ему пространстве в рамках роли |
| Ревьюер/администратор Workspace | Согласование или управление в назначенном контексте |
| Владелец установки | Конфигурирование установки и доступ к `/admin/updates` |
| Оператор хоста | Управление привилегированным агентом, восстановление и откат |

Внешний вход через OIDC или SkiF4er ID не превращает пользователя автоматически в администратора. Связывание аккаунтов и отзыв сессий имеют отдельные проверки.

## Что происходит с контентом

| Функция | Передача данных / настройка |
| --- | --- |
| Обычный Reader | Контент обслуживается своей инсталляцией Book |
| Полнотекстовый поиск | Работает без внешнего провайдера embeddings |
| Embeddings | Внешняя передача возможна только после настройки провайдера; проверяйте политику приватных страниц |
| Чат документации | Внешний OpenAI API включается отдельно; вопрос посетителя запускает запрос; приватные страницы исключены по умолчанию, если явно не изменена конфигурация |
| AI-помощник редактора | Отдельная опциональная интеграция; предварительный просмотр и ревью обязательны перед публикацией предложений |
| Аналитика | Встроенная агрегация и внешние трекеры управляются настройками, согласием и Global Privacy Control |

Полные правила и ограничения: [чат](../admin/documentation-chat.md), [помощник](../admin/editor-ai.md), [embeddings](../admin/search-embeddings.md), [аналитика](../admin/analytics.md).

## Пять правил для production

1. **Не доверяйте исходному ZIP как релизу.** Сверяйте подписанный манифест, SHA-256 и OCI-дигесты независимо доверенным ключом.
2. **Не предоставляйте веб-процессу root и Docker socket.** Используйте задокументированный ограниченный host-agent.
3. **Не обновляйте при активных записывающих процессах.** Проверяйте не только web/worker, но и внешние джобы и PITR-операции.
4. **Не считайте бэкап проверенным до теста восстановления.** Храните данные, ключи и журналы обновлений отдельно, проводите drills.
5. **Не объявляйте production-ready по локальным unit-тестам.** Требуются полные CI, нагрузка, восстановление и проверка именно вашей инфраструктуры.
