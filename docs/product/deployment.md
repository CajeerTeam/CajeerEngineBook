# Развёртывание и первые шаги

[Продукт](README.md) · [Архитектура](architecture.md) · [Администратор](../admin/README.md)

> [!IMPORTANT]
> Эта страница помогает **выбрать путь развёртывания**, но не заменяет проверенную установочную инструкцию. Для production используйте только официальные артефакты с проверенной подписью, фиксированные образы и отдельное окно обслуживания для обновлений. Не выполняйте привилегированные команды из ZIP с изменёнными файлами.

## Выбор режима

| Режим | Где уместен | Что поддерживать |
| --- | --- | --- |
| **File · 1 узел** | Небольшой портал, изолированная установка, знакомство | Приватный постоянный том, резервные копии, HTTPS |
| **PostgreSQL · 1 узел** | Документация с SQL-хранилищем и постоянной эксплуатацией | PostgreSQL 16, схема 7, медиа, резервные копии |
| **Distributed** | Несколько веб/worker экземпляров | PostgreSQL, Redis, общее POSIX-хранилище, наблюдаемость |
| **Enterprise** | Публичный HTTPS, SSO, мониторинг, аварийное восстановление | Отдельные TLS/SSO/backup/PITR и подтверждение RPO/RTO |

## Предварительные условия

- Linux с Docker Engine и Compose `>=2.24.4` для документированных Compose-топологий.
- Встроенный образ приложения с PHP `>=8.4.1`, `<9` и закреплёнными зависимостями Composer.
- Приватное постоянное хранилище **вне** `public/`; для SQL-режима — PostgreSQL 16 и корректная миграция до схемы **7**.
- Для публикации наружу — HTTPS с проверенными ключами и `BOOK_SECURE_COOKIE=1` (базовый Compose использует значение `0` для изолированного HTTP).
- Операционные бэкапы, независимый ключ проверки релиза и отдельный привилегированный аккаунт оператора.

## Порядок новой установки

<details>
<summary><strong>1. Проверить артефакты и подготовить секреты</strong></summary>

Проверьте `source.zip` / `deployment.zip` и OCI-ссылки доверенным ключом Ed25519, идентичность репозитория, версию и commit. Подготовьте закрытый env-файл, Compose project, TLS и место для независимого резервного копирования. Не отправляйте секреты в журналы и не добавляйте их в Git.

[Подписи и проверка](../admin/signed-releases.md) · [Настройка](../admin/configuration.md)

</details>

<details>
<summary><strong>2. Инициализировать владельца и данные</strong></summary>

Следуйте командам сценария **Fresh file-mode installation** или **Fresh PostgreSQL** в [руководстве администратора](../admin/operations.md). Создайте владельца один раз; для существующей установки не повторяйте инициализацию и не запускайте импорт поверх действующей SQL-базы.

</details>

<details>
<summary><strong>3. Запустить сервисы и выполнить health-проверки</strong></summary>

Проверьте `php bin/admin.php check --deep`, `/health/live` и `/health/ready`. Затем создайте организацию и рабочее пространство, назначьте роли и протестируйте публичный и приватный материалы под разными сессиями.

</details>

<details>
<summary><strong>4. Принять эксплуатационные процедуры</strong></summary>

Проверьте восстановление из резервной копии на отдельном хосте, наблюдаемость, план реагирования, журналы аудита, обновления и разрешения на внешние интеграции. Отдельно выполните production-квалификацию **на своей инфраструктуре**.

</details>

## Команды диагностики (из корня проверенной установки)

```bash
php bin/admin.php report
php bin/admin.php check --deep
php bin/migrations.php status
```

`migrations.php status` имеет смысл для установленного SQL-режима; команды диагностируют состояние и не заменяют проверку бэкапов. Не выполняйте `migrate` и `apply --offline` без понимания текущей топологии и полной процедуры остановки записей.
